# 設計決策紀錄

## 初版方向（2026-11-20）

| 項目 | 決策 | 理由與代價 |
|---|---|---|
| 目標玩家 | 沒有程式先備知識的青少年與成人初學者 | 不假設玩家懂英文術語或程式；先建立清楚的動作回饋。年齡跨度仍寬，後續需透過玩家測試調整語氣與難度。 |
| 首發語言 | JavaScript 入門子集 | 遊戲本身在瀏覽器運作，程式結果可以直接改變畫面；無須額外安裝環境。初版只接受白名單指令，避免執行任意程式碼。 |
| 教學順序 | 先教依序執行的指令與函式呼叫，再加入重複與條件 | 第一關把注意力放在「安排行動並觀察結果」，後續再以迴圈解決重複路徑。 |
| 世界觀 | 溫暖、低壓的科幻探索：小型探測機在沉睡星球找回光種，喚醒導航門 | 探索、收集與抵達出口自然形成遊戲目標；錯誤可被包裝成試探路徑，不懲罰玩家。 |
| 核心操作 | 編寫程式 → 執行角色行動 → 看世界回應 → 修改再試 | 讓程式成為遊戲內的工具，玩家藉由結果自行推理，而非回答教學題。 |
| 技術 | 無框架的 HTML、CSS、JavaScript 靜態原型，由 GitHub Pages 發布 | MVP 不需建置步驟，降低迭代成本。指令解析器只解析支援的函式呼叫，不使用 `eval`。 |
| 第一個可玩切片 | 單一任務：收集兩顆光種、避開岩壁、抵達並啟動導航門；提供執行、單步、重設、提示與錯誤回饋 | 先完整驗證「程式指令改變遊戲世界」的循環，再拓展更多關卡。沒有帳號或雲端存檔需求。 |
| 第二關的迴圈 | 以 `repeat(次數, 行動)` 表示重複，限制次數 1–10，解析成逐步播放的白名單行動 | 讓玩家看到重複路程可以縮短程式；保留每一步動畫。此語法是受限的 JavaScript 入門表示法，不等同一般 `for`/`while` 迴圈。 |
| 第三關的條件 | 以 `if (感測器()) 行動();` 寫單行條件；提供光種存在與前方受阻兩種感測器 | 玩家可以在真實關卡狀態下看見條件成立時執行、不成立時略過。解析器只執行白名單條件和動作；暫不支援 `else`、巢狀區塊或任意運算式。 |

## 仍需實際觀察

- 指令編輯器是否比點選積木更容易上手。
- 目前敘事語氣是否同時適合青少年與成人。
- 玩家能否從動畫與提示理解方向、碰撞、收集等規則。
- 初版解析器只接受一行一個、不帶參數的白名單函式呼叫；它是受限的 JavaScript 練習環境，不支援任意 JavaScript、變數、迴圈或條件。
- 第二關的 `repeat` 會展開一個不帶參數的白名單行動；還未支援巢狀、區塊或以一般 JavaScript 撰寫的迴圈。
- 第三關的 `if` 只能檢查已知感測器並執行一個白名單行動；若新手難以理解自訂感測器，應測試後再考慮以更接近一般 JavaScript 的寫法呈現。

## 新手試玩安排

- **未決事項：** 目前沒有真實初學者的使用觀察，因此尚不能判斷提示、遊戲感或 `repeat` 表達是否易懂；開發者自測不能代替目標玩家回饋。
- **建議：** 安排 3–5 位沒有程式先備知識的玩家各自試玩兩關，先不口頭解題；記錄卡關位置、是否看懂地圖與提示、能否描述 `repeat` 的效果，再據此修正。
- **可先繼續：** 在招募前先做鍵盤操作、響應式版面、螢幕閱讀器標記與瀏覽器錯誤的自行檢查，不將自行檢查標作玩家測試。
