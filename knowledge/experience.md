# 開發經驗與後續適用範圍

每筆紀錄說明在本專案實際採用或驗證過的做法，並標示可套用的情境。尚未經玩家測試的設計假設會明確標為待驗證。

## GitHub Pages 靜態發布

- **觀察：** 根目錄提供 `index.html` 的靜態網站可透過 GitHub Actions 上傳 Pages artifact 發布；此專案網址實際回應 HTTP 200。
- **做法：** 使用 `actions/configure-pages`、`actions/upload-pages-artifact` 與 `actions/deploy-pages`；網站內部連結使用相對路徑（例如 `./style.css`），以支援 `/<repository>/` 子路徑。
- **適用範圍：** 不依賴伺服器或建置工具的作品集、互動原型、文件網站和小型瀏覽器遊戲。
- **限制：** 不適合需要私密金鑰、伺服器端運算或個人資料儲存的功能；外部字型載入也會依賴第三方服務。

## 以遊戲行動承載程式概念（待驗證）

- **設計假設：** 讓程式指令控制角色解謎，再立刻展示結果，可能比獨立課程或測驗更能維持遊戲感。
- **預計做法：** 從短指令序列開始，每步提供視覺回饋與可重試的錯誤訊息；待序列概念穩定後再引入迴圈。
- **適用範圍：** 入門程式遊戲、互動教學或需要把抽象指令連結到具體結果的原型。
- **驗證方式：** 觀察新手能否不靠外部說明完成關卡、是否願意修改程式再試，以及是否能說出指令如何影響角色。尚未進行玩家測試前，不把此假設視為已證實。

## 第一個可玩任務原型

- **完成：** 製作一個瀏覽器內可玩的單關任務。玩家用白名單函式呼叫移動探測機，收集兩顆光種並啟動導航門；支援單步、連續執行、重設、碰撞與指令錯誤回饋。
- **驗證：** 在本機瀏覽器實際輸入 13 個行動指令，看到探測機逐步前進、收齊光種並顯示成功狀態；`node --check game.js` 與 `git diff --check` 通過。這只驗證預設任務成功路徑及 JavaScript 語法，不等同新手可用性測試，也未覆蓋所有錯誤分支。
- **觀察：** 以單步與逐步動畫呈現程式執行，可以直接檢查每行指令和位置變化是否對應；用受限解析器保留熟悉的 JavaScript 函式語法，同時避免任意程式執行。
- **適用範圍：** 小型解謎原型、逐步執行的程式教學、瀏覽器端可安全限制指令的互動作品。更動地圖或指令後，至少重跑一條完整成功路徑，確認收集數、座標與成功狀態一致。
- **限制與下一步：** 現在的解析器只支援無參數指令序列，尚非完整 JavaScript；下一個學習關卡可用重複路徑引入迴圈，但應先檢查受限語法是否足以清楚表達迴圈概念。需要安排新手實測，驗證提示、錯誤訊息和整體遊戲感。

## 用重複路徑引入迴圈

- **完成：** 第一關成功後解鎖第二段山谷訊號。第二關用 `repeat(次數, 行動)` 縮短重複的前進指令；關卡逐步播放每個展開後的行動，並提供次數限制與錯誤回饋。
- **驗證：** 在本機瀏覽器完成第一關、進入第二關，輸入 `repeat(2, moveForward);` 等重複指令，成功收齊兩顆光種並啟動導航門。這證明關卡解鎖和迴圈語法主路徑可運作，尚未驗證新手是否明白迴圈含義。
- **觀察：** 先展示一段重複移動，再讓玩家補上另一段同樣長度的移動，可讓迴圈解決的重複直接出現在遊戲目標中。把迴圈展開為有上限的白名單動作，兼顧逐步動畫和不執行任意程式碼。
- **適用範圍：** 教學原型中的固定次數迴圈、可視化逐步除錯、簡單的有限指令語言。
- **限制與後續：** 此 `repeat` 是自訂的受限語法，只重複一個無參數行動；不能代表一般 JavaScript 迴圈。先安排新手說明這行程式做了什麼，再決定要否擴充為區塊語法或真實 `for` 迴圈。

## 可用鍵盤探索任務地圖

- **完成：** 地圖用列與格標記，單一小芽格可用 Tab 聚焦，方向鍵可以移動焦點探索相鄰格；格子標示座標、岩壁、光種和導航門。
- **驗證：** 在本機瀏覽器聚焦小芽格後按向右鍵，焦點移到相鄰格「X 2，Y 5，可通行」；瀏覽器的輔助科技樹也辨識出地圖列與格。
- **適用範圍：** 方格地圖、棋盤、格狀編輯器和需要鍵盤瀏覽位置的互動元件；可用單一 Tab 停靠點搭配方向鍵，減少連續 Tab 造訪所有格子。
- **限制：** 本次只檢查 Chrome 本機 accessibility tree 和鍵盤焦點；尚未用螢幕閱讀器或其他瀏覽器實測，也未確認小螢幕版面。

## 以環境感測器引入條件判斷

- **完成：** 第三關沿用已熟悉的探測路徑，增加光種與岩壁感測器。玩家可寫 `if (感測器()) 行動();`；條件為假時會顯示略過訊息，為真時執行白名單行動。
- **驗證：** 在本機瀏覽器依序完成前三關。第三關起點沒有光種，第一個條件不成立而仍能繼續；抵達光種後條件成立並成功收集；面對岩壁時感測條件觸發左轉，最後成功開啟導航門。
- **觀察：** 重用已熟悉的移動路線可把注意力放在條件與環境之間的關係。讓同一個「是否有光種」條件在不同位置呈現真與假，可以展示條件控制流程的兩種結果。
- **適用範圍：** 入門條件判斷、互動式環境感測、以可觀察狀態變化展示真假條件的教學原型。
- **限制與後續：** `if` 採受限單行語法，只支援兩種感測器和一個行動；玩家測試後再決定是否引入 `else`、程式區塊或一般 JavaScript 表達式。Chrome 本機路徑通過不代表跨瀏覽器相容或學習效果已驗證。

## 儲存已解鎖任務進度

- **完成：** 通關後在目前瀏覽器儲存最高已解鎖任務序號；重開頁面會回到最新解鎖任務，並可用頂端箭頭在已解鎖任務間切換。
- **驗證：** 本機完成第一關後，確認下一關導航可用；前往第二關並重新載入頁面後，仍回到第二關；上、下一段按鈕能在已解鎖任務間往返。
- **適用範圍：** 不需帳號的單機 Web 遊戲、教學原型與短流程互動體驗中的本機進度標記。
- **限制：** 僅保存解鎖序號，不同步不同裝置、不保存玩家編寫的程式；瀏覽器封鎖或清除網站儲存時，進度不保證保留。這次只在本機 Chrome 驗證，尚未跨瀏覽器測試。

## 編輯器與動態地圖的鍵盤體驗

- **完成：** 讓 Tab 和 Shift+Tab 可離開程式編輯器；單步途中修改或插入指令後，下一次執行從起點重新解析。每次更新地圖時重新組合格子的座標、角色、方向和地標狀態，並提供方向鍵操作提示。
- **驗證：** 以桌面 Chrome 和 Edge 的 375px 模擬視窗檢查頁面無水平溢出、Tab 可離開編輯器、方向鍵可探索地圖、角色移動與收集後標記正確、修改程式後重新開始，以及第一關完整通關；`node --check game.js` 和 `git diff --check` 通過。
- **適用範圍：** 逐步執行且允許中途修改的編輯器，以及包含可移動角色與可變地標的鍵盤方格地圖。修改來源時應使已解析的執行計畫失效，動態標記則應從當前狀態重新產生。
- **限制：** 這是自動化瀏覽器和模擬視窗檢查，不等同實體手機、螢幕閱讀器或初學者實測；Firefox、Safari 和不同螢幕尺寸仍待檢查。

- **觀察與修正：** 721px 視窗仍採雙欄，但地圖比左欄寬，右側因容器裁切而消失。將單欄斷點提前至 760px，並在窄視窗放大主要文字、編輯器與操作按鈕；可鍵盤操作的控制項增加明顯焦點框。
- **驗證：** 桌面 Chrome 模擬 320、375、480、720、721、768、800、920、921、1024、1440px，測量地圖邊界及頁面寬度，未見地圖裁切或整頁水平溢出；檢視 320px 畫面，並重跑 Chrome、Edge 的 375px 基本操作與第一關通關。
- **適用範圍：** 固定格數地圖與雙欄編輯工作台；檢查斷點兩側與元件實際邊界，不能只看整頁是否有水平捲軸，因為 `overflow: hidden` 可能掩蓋裁切。
- **限制：** 模擬視窗與桌面瀏覽器無法取代實體手機、觸控或行動版 Safari 的測試；較長程式行仍可在編輯器內水平捲動。

## 任務結束和重設時的焦點與狀態

- **完成：** 當光種收齊、角色抵達導航門但程式結束時，提示玩家加入啟動指令；通關畫面顯示時隱藏被覆蓋的地圖並將焦點移至下一步，重新遊玩時回到編輯器。
- **驗證：** 桌面 Chrome 自動逐步完成三關，檢查條件略過、抵達門後的提示、通關焦點、重新遊玩、重新載入後的解鎖進度，以及執行途中重設後延遲回呼不再移動角色。
- **適用範圍：** 以程式驅動的多階段互動、可中止的動畫與覆蓋式成功畫面。畫面狀態切換時，應同步處理焦點和被遮住的內容；中止非同步流程時，應讓舊回呼失效。
- **限制：** 自動化檢查未涵蓋實際螢幕閱讀器的播報或新手是否理解提示。

## 地圖焦點停靠與解析錯誤檢查

- **觀察與修正：** 方向鍵移到小芽之前的格子後，原本的小芽格仍是 Tab 停靠點，按 Tab 會回到地圖而非繼續。現在方向鍵移動時一併轉移唯一的 Tab 停靠點；地圖重繪時保留正在探索的格子。
- **驗證：** 桌面 Chrome 檢查方向鍵後 Tab 離開地圖、Shift+Tab 回到探索格；並檢查空程式、無效語法、未知指令、尚未解鎖的語法、repeat 次數和總步數上限、未知感測器與任意程式碼均顯示錯誤。三關成功流程再次通過；Pages 的 CSS 回應 HTTP 200 且包含前一階段行號修正。
- **適用範圍：** 以方向鍵探索、單一 Tab 停靠點的格狀元件，以及採白名單和執行上限的互動指令解析器。
- **限制：** 這些檢查不涵蓋所有格式、瀏覽器或輔助科技；錯誤訊息是否讓初學者理解仍需實際試玩。

## 補查 WebKit 引擎

- **驗證：** 在 Windows 使用 Playwright 的 WebKit 26.5，以本機 HTTP 網站和 375px 模擬視窗檢查整頁寬度、地圖鍵盤導航、三關逐步通關、任務解鎖及重新載入後的進度，未觀察到頁面程式錯誤。
- **適用範圍：** 靜態網頁在不同瀏覽器引擎上的基本回歸；以本機 HTTP 而非檔案網址測試儲存等瀏覽器行為。
- **限制：** Windows 上的 WebKit 不等於 macOS／iOS Safari，模擬視窗不等於實體裝置。這次下載的 Playwright Firefox 因 Windows 無法解析 `mozglue` 並列組件而無法啟動，Firefox 尚未完成測試。

## 保留最後一步的行動回饋

- **完成：** 狀態列在成功行動時顯示程式行號，前進時也顯示新座標；程式結束提示接在最後一步或條件略過的訊息後。視覺提示不再是另一個即時播報區，以免與狀態列重複。
- **驗證：** 桌面 Chrome 檢查單行行動的行號、座標與結束提示，以及最後一行條件為假時保留略過訊息；另重跑三關成功流程、鍵盤導航和解析錯誤檢查。
- **適用範圍：** 逐步執行的程式遊戲或模擬器，尤其是需要把來源行、世界狀態與最終結果連結起來的介面。
- **限制：** 狀態內容經自動化檢查，實際螢幕閱讀器播報與新手理解仍待測試。

## 本機進度儲存失敗與多分頁

- **完成：** 讀寫儲存失敗時顯示無法保存的訊息，但仍讓玩家在目前頁面繼續解鎖；保存前合併現有的最高進度，並接收其他分頁的更新。
- **驗證：** 桌面 Chrome 模擬 `localStorage` 存取遭拒，確認第一關通關後可在當前頁面進入第二關並顯示提示；兩個分頁中先寫入第三關進度，再從舊分頁完成第一關，確認第三關進度未被覆蓋。另重跑三關流程與解析錯誤檢查。
- **適用範圍：** 以本機儲存保存單調遞增進度的遊戲或互動工具；儲存狀態應反映實際寫入結果，且更新前應合併已保存的較高值。
- **限制：** 這不是跨裝置同步或通用交易機制；儲存不可用、清除資料或不同瀏覽器都可能失去進度。

## 持續推送與發布順序

- **觀察與修正：** 原本整個 Pages 工作流程共用取消中的 concurrency 群組，後續推送會取消前一次尚未完成的測試；公開網站曾落後於已推送的變更。改為各次測試獨立執行，只有發布工作序列化，並在發布前比對該提交是否仍為遠端 `main`。
- **驗證：** 本機以臨時 Git 儲存庫檢查最新提交可發布、過時提交跳過、遠端不可讀及版本格式無效時失敗；完整 Chrome 回歸與發布判斷測試通過。GitHub 實際連續執行兩次推送，三引擎測試均成功，較舊提交跳過發布、較新提交成功發布；公開網站回應 HTTP 200 並包含回聲日誌與足跡。
- **適用範圍：** 頻繁推送、測試耗時且只應發布最新分支版本的靜態網站；發布前再檢查遠端版本，避免較晚完成的舊測試覆蓋新版。
- **限制：** 發布開始後若又有新提交，舊版仍可能短暫上線，直到新版通過測試並發布；若遠端讀取失敗，流程會失敗而不猜測是否可發布。

## Firefox 的捲動控制台焦點

- **觀察與修正：** GitHub Actions 的 Firefox 在從地圖按 Tab 後沒有直接進入編輯器，導致兩次發布前測試失敗；Chrome 和 WebKit 的同一檢查通過。控制台是可捲動容器，先明確設定不加入 Tab 順序，並在測試失敗時記錄實際焦點元素以利釐清。
- **驗證：** 本機 Chrome 與 WebKit 的鍵盤檢查通過；本機 Windows 的 Playwright Firefox 啟動失敗，但 GitHub Linux 的 Firefox 完整測試在修正後連續兩次通過。
- **適用範圍：** 包含可捲動容器與方向鍵地圖的跨瀏覽器遊戲介面；對照實際焦點元素，不把單一瀏覽器的 Tab 順序視為通用結果。
- **限制：** 尚未確認捲動容器就是修正前 Firefox 的實際停靠點，也尚未以螢幕閱讀器實測。

## 以兩組機關延伸探索

- **完成：** 第五關使用 A、B 兩組各自控制的開關與光閘。玩家需要先啟動 A 進入下一區，再啟動 B，穿過光閘找回第二顆光種後返回導航門；兩組機關有字母與顏色標示，並各自重設。
- **驗證：** 本機 Chrome 的 29 項回歸通過，包括五關完整通關、A 開啟時 B 仍阻擋、依序啟動與重設；WebKit 的五項相關檢查也通過，另檢視 320px 第五關畫面。
- **適用範圍：** 已熟悉基本開關後、需要規劃多段路線的方格冒險；多組機關應各自保存狀態，並以不只顏色一種方式表明配對關係。
- **限制：** 先前版本的進度只記住最高已解鎖關卡，無法區分「已抵達第四關」與「已完成第四關」；既有玩家需再次完成第四關才能解鎖第五關。謎題的難度與趣味仍需初學者試玩。

## 保存最後一關的完成狀態

- **觀察與修正：** 只保存最高已解鎖關卡時，完成當時最後一關仍會留下相同序號，新增關卡後無法判斷玩家是否已通關。現在另存最高已完成任務，新增關卡時可根據完成紀錄解鎖下一段；舊存檔仍依可確定的已解鎖進度繼續。
- **驗證：** 瀏覽器回歸檢查最後關卡完成紀錄、模擬新增關卡後解鎖、舊存檔與無效紀錄，以及多分頁完成紀錄合併。
- **適用範圍：** 會持續增加關卡、以瀏覽器儲存單機進度的遊戲；解鎖與完成是不同狀態，不應只靠同一個上限序號推斷。
- **限制：** 對舊版未記錄的最後一關完成狀態仍無法追溯；儲存失敗、清除資料及更換裝置都可能失去進度，多分頁合併也不是跨裝置同步。

## 以可推動光晶改變道路

- **完成：** 第六關讓小芽用前進指令推動光晶，把光晶留在底座上才能保持光閘開啟。後方沒有空間時不能推；光晶離開底座會關門，前方阻擋感測器會依光晶是否推得動回應。
- **驗證：** 本機 Chrome 完整回歸與 WebKit 的關卡、機關及推動檢查通過；另檢查玩家站上底座不會誤開門、推動與移開的狀態、受阻及重設，並檢視 320px 畫面。
- **適用範圍：** 以位置、物件與機關互相影響的方格解謎；行動、感測器、文字標示與地圖應使用相同的碰撞與機關狀態。
- **限制：** 目前只有一顆光晶；玩家可能把它推到無法繼續的位置，需要重設。關卡是否有趣、物件與底座是否好辨識仍需玩家及實體裝置測試。
